--------------------------------------------------------------------------------
0. NON-NEGOTIABLE RULES (violating these = failure)
--------------------------------------------------------------------------------
1. WIRE-FORMAT FIDELITY. The bytes on the wire must match the Python server
   exactly. Do NOT "improve" or "modernize" the protocol. Do NOT "fix" field
   numbers that differ from public POGOProtos — they were verified against the
   live client. Known intentional differences you MUST preserve:
     - RequestEnvelope.requests is field #4 (not #3)
     - PokemonData.id is a fixed64 (not int32)
     - Everything in src/server/windstock/game/pb.py is ground truth.
2. Node.js 21 ONLY. ESM ("type":"module"). Use node: builtins
   (node:http, node:https, node:net, node:tls, node:crypto, node:dns,
   node:child_process, node:fs, node:sqlite is NOT allowed — Node 21 lacks it).
   Zero-dependency is preferred. ALLOWED external packages ONLY:
     mysql2        (MariaDB driver)
     better-sqlite3(SQLite, replaces database.py SQLite backend + server storage)
     (everything else must use node core. If you think something else is
      required, implement it yourself and note it in the blueprint.)
3. NO Python runtime. No exec'ing python, no python subprocesses, no py files.
   Tools that were Python are ported to JS. The only external programs allowed:
   openssl (via child_process) for certs, npx apk-mitm (the patcher's job).
4. Behavior parity over code brevity. When unsure what the Python does, read it
   and copy behavior exactly. Note assumptions in the blueprint.
5. No dead ends. A session must always leave runnable code. Any optional/unbuilt
   path must throw a clear `new ERRNOTIMPLEMENTED("MODULE.PATH — see REWRITE_STATE.md")`.
6. Data files stay data. settings.json, places.json, biomes.json, cpdata.json,
   saves/*.json, certs/, data/osm_biomes.json keep their names and formats.
7. Never stop to ask the user for routine decisions. Decide, implement, log the
   decision in REWRITE_STATE.md under "Decisions". Only stop for a genuinely
   ambiguous protocol meaning that no file in the repo clarifies.

1. THE BLUEPRINT MECHANISM (how sessions remember each other)
--------------------------------------------------------------------------------
File: REWRITE_STATE.md (repo root). It is the project's long-term memory and
inter-module contract. Structure it in reverse-chronological session entries:

  ## Session NN — <module name>  (date, model used)
  ### Exported API
    - exact module names / exports / signatures (types = JS docs comments)
  ### Contracts relied on
    - what this module imports from not-yet-built modules and the exact shape
      it expects (so a later session can match it)
  ### Decisions
    - every behavioral call made while porting (field sizing, error text, etc.)
  ### Stubs created
    - anything thrown as ENOTIMPLEMENTED and who must fill it
  ### TODO
    - open items the next sessions inherit (keep this list SHORT)

Each session reads this file first, ports its module to match the contracts in
"Contracts relied on" exactly, and finishes by appending a fresh "Session NN"
entry. Do not rewrite past entries; append only. When an earlier session turns
out wrong, note it in the new entry and fix it in the code (code beats notes).

2. CHUNK PLAN (fixed build order — later modules import earlier ones)
--------------------------------------------------------------------------------
Port in install order. "Stub" = write the export with a throwing body now.

  00  Skeleton infrastructure
      package.json (ESM, engines node>=21), REWRITE_STATE.md seed, logging
      module, error hierarchy, test harness (node:test), npm scripts.
      Output: `npm test` runs green with one smoke test.

  01  pb.js — protobuf reader/writer
      Port src/server/windstock/game/pb.py verbatim. This is the codec EVERYTHING
      uses. Build byte-exact fixtures: capture encode/decode pairs as hex strings
      (from the Python semantics, hand-crafted for varint, fixed64, packed,
      nested, repeated) into test/fixtures/pb.json. This is the most tested file
      in the project. Wire helpers = the public interface you test first.

  02  config/  (paths, settings, places, events)
      Port config/paths.py, config/settings.py (incl. hot-reload watcher),
      config/places.py, config/events.py. Expose a config object consumed by all.

  03  geo/    (S2, biomes, pois, poidownload)
      - S2: implement the S2 cell math in pure JS (port what s2sphere was used
        for — you do NOT get to use the npm package). Cover lat/lng <-> cellid,
        covering for the map cells used by geo/biomes and geo/pois. Write unit
        tests with known lat/lng -> hex cellid vectors.
      - biomes.py, pois.py, poidownload.py: same behavior; OSM Overpass via
        node:http, cached like the Python does. osmium is NOT ported — if OSM PBF
        parsing is needed, implement a minimal PBF decoder (varint/zigzag tiles)
        in JS and note it. Prefer the same Overpass path the Python used.

  04  database — the backup/restore tool (database.py) + server persistence
      Port database.py (MariaDB via mysql2 + SQLite via better-sqlite3, same
      console commands) AND the save/load logic that world.py serializes
      (data/saves/<name>.json, same on-disk shape).

  05  game data  (gamedata, cpdata, leveling, shop core)
      No protocol yet — just pure computations and tables. Export lookups and
      level/IV math that rpc.py will call. Unit-test the level curve numbers.

  06  protocol.js — THE BIG ONE (MANDATORY CHUNK CHAIN, NEVER one session)
      Port src/server/windstock/game/protocol.py (~292 KB). It is the heart.
      HARD RULE: protocol.py MUST ALWAYS be ported across multiple sessions in
      an unbroken CHUNK CHAIN. No single session ever touches all of it. Each
      session ports exactly ONE complete top-level group and ends by writing
      NEXT_PROMPT.md that assigns the NEXT protocol chunk as the next session
      (06a -> 06b -> 06c -> ...), with the exact next range of the Python file,
      until the file is fully covered and the chunk chain is marked done.
      Required chunk split (never renegotiate the order):
        06a  handshake + map builders
        06b  encounter + catch
        06c  gyms
        06d  shop + inventory
        06e  every remaining request type + asset digest/settings builders
      Count every request type the Python handles across the chain — every one
      gets a builder, and the last chunk (06e) audits ALL of them against a
      checklist in REWRITE_STATE.md to prove none were dropped between chunks.
      This module ONLY builds responses; it imports pb.js and config and world.
      The chunk chain has TOP PRIORITY: while protocol.js is unfinished, the
      NEXT_PROMPT.md must ALWAYS point at the next protocol chunk — no other
      module may jump the queue.

  07  rpc.js — protocol routing
      Port game/rpc.py: the boot handshake sequence (redirect -> player ->
      remote config -> settings -> asset digest -> item templates -> map), the
      71 request types dispatched, and error handling. Wire protocol entrypoint
      is the request/response envelope. Byte-for-byte request handling.

  08  world.js — shared state
      Port game/world.py: per-account inventory/pokemon/xp, shared gyms,
      atomic item operations, save-to-disk lifecycle, deleting a save resets
      the player. Must be dependency-injected so rpc and web both use it.

  09  net/  (server, sso, sso_bridge, dns_redirect, certs)
      - TLS listener that routes by Host header (game vs PTC hosts).
      - Fake PTC SSO (any creds, username embedded in token).
      - 0.35 SSO bridge (plain-HTTP login).
      - DNS redirector (node:dns or a raw UDP responder on port 53 answering
        for Niantic/PTC hosts, forwarding everything else) — port behavior.
      - cert generation via openssl child_process (same certs/ layout).
      First milestone: the full fake-client probe (port tools/test_login.py and
      probe.js end-to-end flows) passes.

  10  web/  (website, helpcenter, admin, webui = World Manager)
      Port helpcenter.py, website.py, admin.py, webui.py. admin.py is ~50 KB —
      may be split, but one logical area per session. Serve SAME URLs/routes on

  11  cli + ui  (console.py, pogo_manager.py, theme, logfile, network)
      The slash-console (World Manager cli) ports 1:1. pogo_manager.py is a

  12  tools/  (convert_gm, metadata*, asset/bundle, download helpers, etc.)

3. ANTI-STUCK RULES (read these before every session)
--------------------------------------------------------------------------------
- **Unlimited tokens do NOT mean infinite context.** Keep REWRITE_STATE.md
  tight: interfaces, not prose. THE BIG BLUEPRINT is contract-only and
  scannable in one read (< ~5 min); expand it, never duplicate it.
- **Never block on an un-built dependency.** If session 06 needs world.js and
  08 isn't built yet: import it as `import * as world from '../game/world.js'`
  even if the file is only a stub of throwing functions, and code against the
  CONTRACT you wrote down. That contract is binding; 08 must match it.
- **Never ask the user anything that has an answer in this repo.** Read files
  until the answer is found. If truly undecidable, pick the behavior that
  preserves client compatibility, log it, move on.
- **One logical task per session.** Splitting protocol.py is fine; splitting a
  mid-function is not. Finish a unit of work to a test-passing, runnable state.
- **Big files split by surface, not by line.** A 5,000-line module becomes
  folder modules (e.g. game/protocol/handshake.js, encounter.js) re-exported
  through an index.js. Never duplicate logic across them.
- **Always leave the tree in a state where `npm test` runs.** Pending work is a
  throwing stub + a TODO line, not a comment saying "later".
- **If tests fail, fix the tests' expectations only when the PYTHON code proves
  the test wrong.** Python is truth. The test harness reproduces Python
  behavior; do not rewrite the harness to fit a sloppy port.
- **Output the report in the required format** (below), no excuses, even if
  partial. A written report beats silence.
